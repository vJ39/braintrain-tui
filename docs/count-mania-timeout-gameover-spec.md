## 概要

カウントマニアに以下3点の仕様変更を行う。

1. 間違った場所をクリックした時、クリックした箇所に赤いバツ印を数秒間表示する
2. 何もクリックしないまま一定時間が経過した(時間切れ)場合、押すべき番号の円を数秒間点滅させてからGAME OVERに遷移する
3. 焦らせるプレッシャー背景(グラデーション)の発生閾値・時間切れ閾値を変更する

## 対象ファイル

- `src/game/count_mania/mod.rs`

## 1. 誤クリック時の赤いバツ印表示

- `handle_mouse`が`click_wrong()`を呼ぶ箇所で、クリックした座標(column, row)を渡すようにする(`click_correct`が既に座標を受け取ってRippleを生成しているのと同じ形)
- 座標を受け取った`click_wrong`は、その座標に赤いバツ印(✗)を一定時間(例: 1.5秒程度。具体的な秒数は実装時に見た目のバランスで決めてよい)表示する状態を保持する
- 表示状態は既存の`ripple: Option<Ripple>`と同様に「開始時刻からの経過時間で消える」パターンで実装する(新しい構造体`WrongMark`等を追加し、`update`で経過時間を進め、持続時間を超えたら`None`に戻す)
- `render`で、正解の波紋(Ripple)と同様にこのバツ印を描画する(色は赤系統)
- ライフが尽きてGAME OVERになるクリックでも、そのクリック位置には同様にバツ印を出してよい(GAME OVER演出と共存する)

## 2. 時間切れでのGAME OVER(点滅→遷移)

- `Round.time_since_target`(現在の対象の数字が「次に押すべき」になってからの経過時間)が一定の上限に達したら、何もクリックしなくてもGAME OVER(ライフ0の時と同じ`game_over = true`の扱い)にする
- GAME OVERになる直前の数秒間は、押すべき番号の円を点滅させて警告する
  - 時間切れ上限に達する数秒前(具体的なリード秒数は実装時に決めてよい。目安2〜3秒)から、対象の円(`round.next`の番号)を明滅させる描画にする
  - 正解をクリックすれば`time_since_target`は0にリセットされる(既存の`click_correct`の挙動のまま)ので、点滅・時間切れ判定も自然と解除される
- 時間切れでGAME OVERになる時のフィードバックメッセージは「ライフが尽きた」ではなく、時間切れであることが分かる文言にする(例: 「時間切れ」)
- 時間切れによるGAME OVERも、ライフ切れと同じく次のラウンドへの待ち時間には入らず、フィードバック表示が消えたらセッションが終了する(既存の`game_over`フラグの挙動をそのまま使う)

## 3. プレッシャー背景・時間切れの閾値変更

- `PRESSURE_THRESHOLD`(現在10秒)を5秒に変更する
- 新たに時間切れの上限(GAME OVERになるまでの`time_since_target`)を12秒とする定数を追加する
- 点滅開始のタイミングは、この12秒の上限から数秒前(上記2章の目安2〜3秒前)に設定する

## テスト観点

- 誤クリックでクリック位置にバツ印が表示され、一定時間後に消えること
- 正解クリック時・GAME OVER時の既存の波紋・フィードバック表示に、バツ印が干渉しないこと
- `time_since_target`が上限(12秒)に達すると`game_over`がtrueになること
- 上限の数秒前から、押すべき番号の円が点滅表示になること(既存の`pressure_background`と同様、時間で見た目が変わることを確認するテストパターンで書ける)
- 時間切れGAME OVER時のフィードバックメッセージが時間切れであることを示す文言になっていること
- 正解クリックで`time_since_target`がリセットされ、点滅・時間切れ判定も解除されること
- `PRESSURE_THRESHOLD`が5秒になったことを確認する既存テストの更新
- 既存の`board_background_resets_on_game_over`等、GAME OVER関連の既存テストが壊れていないこと
