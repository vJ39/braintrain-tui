## 概要

「カウントメニア」の盤面(背景)を水槽に見立て、AQUATERM(vJ39/aquaterm)の魚を参考にした魚を泳がせる。円に当たらなかったクリックがあると、その近くの魚が驚いて逃げる。数字の円のゲーム性(視認性・当たり判定)は変えない。

## 参考にする既存実装(AQUATERM)

AQUATERM自体は育成シミュレーション(空腹・病気・繁殖・捕食等)のフル機能を持つが、今回移植するのは以下の考え方だけで、コードはコピーせず新規に軽量実装する。

- ランダムウォークで泳ぐ(速度に毎フレーム小さなランダム加速度を加え、上限速度でクランプ)
- 驚き逃走(`flee_timer`/`flee_dx`/`flee_dy`): 刺激を受けた瞬間に残り時間と方向ベクトルをセットし、残り時間がある間は強い加速度をその方向へ加え続ける。時間経過で0になれば通常のランダムウォークへ戻る
- 水槽の壁(盤面の端)に当たったら速度を反転させ、向き(`facing_right`)を反転する

## 変更内容

- `src/game/count_mania/fish.rs`を新設する
  - `struct Fish { x: f64, y: f64, vx: f64, vy: f64, facing_right: bool, flee_timer: f64, flee_dx: f64, flee_dy: f64 }`(座標はセル単位の連続値)
  - 定数: `WANDER_ACCEL`(ランダムウォークの強さ)・`MAX_SPEED`(セル/秒)・`FLEE_DURATION`(1.2秒)・`FLEE_ACCEL`(逃走時の加速度、`WANDER_ACCEL`よりずっと大きい値)
  - `Fish::new(x, y) -> Self`
  - `Fish::update(&mut self, dt: Duration, bounds: Rect, rng: &mut impl Rng)`: ランダム加速→(flee_timer > 0なら逃走加速を上乗せしflee_timerを減らす)→速度をクランプ→位置を更新→boundsの端で反射(速度反転+`facing_right`更新)
  - `Fish::spook(&mut self, from: (f64, f64))`: `from`(クリック位置)から自分への方向ベクトルを正規化して`flee_dx`/`flee_dy`にセットし、`flee_timer = FLEE_DURATION`(すでに驚いている間に再度spookされても違和感がないよう、`flee_timer`を`FLEE_DURATION`まで伸ばすだけで方向は上書きする)
  - 見た目: 画像プロトコル対応端末は小さなドットマトリクス(6〜8行程度、AQUATERMのネオンテトラ成魚パターンを参考にした軽量な新規デザイン1種で十分)を`recolor`(count_mania/circle_image.rsの関数を再利用)して色を付け、`facing_right`に応じて左右反転して描画する。非対応端末は`"><>"`/`"<><"`(向きに応じて反転)のテキストで代用する
- `count_mania/mod.rs`の`CountManiaGame`に`fish: Vec<Fish>`(2〜3匹)を追加する
  - `update(dt)`で各魚を`update`する(ラウンド間の待ち時間・GAME OVER後も泳がせ続けてよい。水槽の生き物なのでゲーム進行と無関係)
  - `render`で、円を描く前に魚を`board`全体に描く(円が最前面になるよう、魚は円より先に描画する)。画像プロトコル対応端末では、魚の位置(テキスト表示と同じく丸めたセル位置)・向き・色を`BoardFish`として`CircleRenderer::render_board_with_fish`に渡し、円の描画器が描く
  - `handle_mouse`の「円に当たらなかったクリック」の分岐(既存の`hit_test`が`None`を返すケース)で、クリック位置から一定距離以内の魚(全部でよい)に`spook`を呼ぶ。円に当たったクリック(正解・不正解とも)では魚は反応しない

## 画像表示での魚の描き方(circle_image.rs)

盤面は1枚の画像として端末へ送っているため、魚は波紋・バツ印と同じく「盤面の画像の上に重ねる小さな画像(パッチ)」で描く。

- 盤面の画像を作る時(円の並びが変わった時)は、その時の位置の魚も円の後ろに描いて送る
- その後セルを移った・向きを変えた魚だけ、前の位置と今の位置を合わせたセル範囲のパッチを作る。パッチは円だけの盤面画像から切り出し、魚を円の後ろ・波紋とバツ印を円の手前に重ねる(前の位置も描き直すので古い魚が残らない)
- 同じフレームのパッチ同士が重なる・左右に隣り合う時は1枚にまとめる(波紋・バツ印のパッチも含む)
- パッチも魚も盤面の左端2列には置かない・描かない
- 同じ起点へ前回と同じ画像のパッチを置くことになった時は、範囲を1セル広げて別の画像にする(ImageDedupBackendが同じ位置へ同じ画像データを送り直さないため)
- 波紋・バツ印が消えたら、何も重ねていない切り出しを1回描いてその範囲を手放す
- ラウンド間の待ち時間は盤面の画像を描かないため、画像表示では魚も表示しない(泳ぎ続け、次のラウンドの盤面に描く)

## テスト観点

- `Fish::update`: 十分な時間(数秒)動かすと、ランダムウォークだけで盤の境界内に留まる(常にboundsの中にいる、境界で反射する)こと
- `Fish::spook`後、`flee_timer`が`FLEE_DURATION`になり、`flee_dx`/`flee_dy`が単位ベクトル(長さ1)になっていること。方向はクリック位置の反対側であること
- `spook`直後の`update`は、通常時より大きく移動する(逃走加速が効いている)こと
- `flee_timer`が0になった後は通常のランダムウォークに戻ること(強制的な移動が続かないこと)
- 円に当たったクリック(正解・不正解とも)では魚の`flee_timer`が変化しないこと
- 円に当たらなかったクリックでは、近くの魚の`flee_timer`が増えること
- `render`が魚ありでもpanicしないこと(画像プロトコル対応・非対応の両方、極端に小さいareaでも)
