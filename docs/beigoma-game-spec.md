## 概要

新規ゲーム「べー」。軽トラの荷台に載った女の子キャラが持つベーゴマ盤の上で、高速回転するベーゴマを操作し、盤上の唯一のゴールへ導く。軽トラの走行イベント(段差・信号・障害物回避)のたびに盤にGがかかり、盤上の障害物(凹凸)に触れた瞬間のGの大きさによってベーゴマが弾かれたり吹っ飛んだりする。制限時間60秒。吹っ飛んだら即GAME OVER。

この設計は初版をfableでレビューし、指摘を受けて改訂したもの(操作方法の実装可否・盤面描画のコスト・物理式の不備等)。

## 操作: 連打式・2軸

- 盤の傾きは前後軸・左右軸の2軸で持ち、それぞれ`-4`(最大後傾/左傾)〜`+4`(最大前傾/右傾)の符号付き値で表す(0=水平)
- 上下キーで前後軸、左右キーで左右軸を操作する。**押しっぱなしでの連続変化ではなく、キーを押すたびにその方向へ一定量(例: 0.7)傾きを動かす連打式**にする(端末のキー入力は押下イベントのみで離鍵を検知できないため)
  - 連打が速いほど単位時間あたりの押下回数が増え、結果として傾きが速く最大値へ到達する。ゆっくり連打すればゆっくり到達する
  - キーを押していない間は、時間経過に応じて傾きが徐々に0(水平)へ自然減衰する(例: 1秒あたり一定量ずつ0に近づく)
  - 反対方向のキーを押すと、その軸の傾きを逆方向へ動かせる
- 盤の傾きに応じて、ベーゴマは慣性・摩擦のある物理(簡易な2D的な速度・加速度)で転がる。プレイヤーは連打の強さ・タイミングで傾きを調整してベーゴマを誘導し、ゴールに導く

## 軽トラの自動走行とGイベント

軽トラはプレイヤーの操作を介さず自動で走り続ける。以下のイベントが時間経過に伴い発生し、そのたびに盤にGがかかる。Gは軸(前後・左右)と大きさを持つ瞬間値で、盤の傾き操作とは別に、ベーゴマの速度に外力として加わる。

1. **段差**: 下からの衝撃。前後軸のGとして扱う(段差通過時の垂直衝撃を、盤面上は前後方向の揺れとして表現する)
2. **信号機**: 黄色/赤色で減速する(制動力=Gの大きさは、信号までの距離とブレーキを踏むタイミングに応じて変わる)。前後軸のGとして扱う(ブレーキ=後方向、発進=前方向)
3. **障害物回避**: 走行中に前方に障害物が現れ、右左折で避けようとした瞬間に横方向のGが発生する。左右軸のGとして扱う

軽トラ視点(2視点のうち片方)は「通常時」「踏ん張り時(Gがかかった瞬間)」の2枚の静止画を切り替えて見せる(常時アニメーションはしない)。信号は色が変わる瞬間を軽トラ視点の背景要素として表示し、プレイヤーはこれを見てGが来る前に盤の傾きを調整して備える。「気づくタイミング」は、信号が黄色に変わってからゲーム側の判定までの経過時間で決める(決められたロジックで良い。実装時に具体化する)。

## 盤上の障害物(凹凸)と摩擦・吹っ飛び判定

- 盤上には具体的な障害物(凹凸)と唯一のゴールを、あらかじめ決めた固定配置で置く(毎回ランダム生成しない。決まったコースを繰り返しプレイして上達できるようにする)
- 平坦な場所(障害物が無い場所)では、Gの大小に関わらず摩擦は通常のままで、ベーゴマは普通に転がる
- ベーゴマが障害物(凹凸)を踏むと、そのままではなく一度飛び上がる。着地する瞬間の摩擦は、踏んだ時にかかっていたGの大きさに応じて増える。この「増えた摩擦」の大きさで3段階の結果になる
  - 摩擦が高い閾値を超える → ベーゴマが吹っ飛び、即GAME OVER
  - 摩擦が低い閾値は超えるが高い閾値には届かない → 吹っ飛びはしないが、ボード上を勢いよく("ピューン"と)弾かれるように移動する(位置・速度が急激に変わる)
  - 摩擦が低い閾値以下 → 通常の転がりに近い、軽い着地で収まる

## 軽トラの走行physics(Gの求め方)

Gの値は固定値やランダム値ではなく、軽トラの速度・加速度を運動方程式でシミュレートして求める。軽トラは常に「現在速度」を持ち、以下のイベントごとに目標速度・目標横位置と、そこに至るまでの残り距離/残り時間から必要な加速度を逆算し、その加速度の大きさをGとして盤に伝える。

- **巡航**: 通常は一定の巡航速度で走る。加速度0、Gなし
- **信号でのブレーキ**: 信号までの残り距離 `d` と現在速度 `v` から、「その信号の手前で確実に止まるために必要な減速度」を `a = v^2 / (2 * d)` で求める。`d`が極端に小さい値にならないよう下限をクランプする(発散防止)。プレイヤー(というよりゲーム側の仮想ドライバー)が信号の色に気づくタイミングが遅いほど、気づいた時点の`d`が小さくなり、結果として`a`(=制動G)が大きくなる
- **信号での発進**: 青になったら、巡航速度に戻るまで一定の目標加速度で加速する。この加速度の大きさが発進時のGになる
- **障害物回避(操舵)**: 障害物までの残り距離`d`と現在速度`v`から、避けるために必要な横方向の移動量(車線変更相当の距離)を、時間`t = d / v`の間に完了させると仮定し、必要な横加速度を`a_lateral = 2 * lateral_distance / t^2`(等加速度運動の公式)で求める。距離が近い・速度が速いほど`t`が短くなり、横Gが大きくなる
- **段差**: 段差の高さ・軽トラの速度から衝撃の大きさ(前後軸のGとして扱う)を決める。単純化した式(速度に比例する等)でよい

数値感の目安: 巡航速度を40km/h(約11m/s)程度とした場合、信号までの距離20mで減速すると約0.3G、5mまで気づくのが遅れると約1.2Gになる計算。摩擦増加の閾値は、低=0.3G相当・高=0.8G相当を目安にする(実装時に見た目のバランスで調整してよい)。

これらの式の係数・具体的なロジック(信号の距離・障害物の出現位置等)は実装時に見た目のバランスで決めてよいが、「Gがランダムな数値ではなく、軽トラの速度・距離から運動方程式で導かれている」ことを保証すること。

## 盤面描画(パフォーマンス制約)

カウントマニア(`count_mania/circle_image.rs`)と同じ考え方を踏襲する。画像プロトコル使用時、盤面(障害物・ゴール)は固定なので1回だけ合成・キャッシュし、動く要素(ベーゴマ)の位置が変わった時だけ、前回位置と今回位置を包む小さな矩形(パッチ)だけを再エンコードして盤面の上に重ねる。盤面全体を毎フレーム作り直さない。

軽トラ視点は「通常時」「踏ん張り時」の2枚の静止画を、Gがかかっている間だけ切り替えるだけなので、この視点側の描画コストは低い。

## 進行・終了条件

- 3.2.1.GO!! の演出(既存の`ui::countdown`を再利用)の後、ベーゴマが盤上に投入され回転を始める
- 制限時間60秒
  - 60秒以内にゴール(盤上の唯一のマス)にベーゴマが到達したらクリア成功
  - 吹っ飛んだら即座に失敗としてGAME OVER
  - 60秒経過してもゴールしなければ時間切れで失敗
- リザルトには成功/失敗と、成功時はクリアタイムを記録する(他のゲームと同様`GameResult`・`ScoreTracker`の仕組みに乗せる)
- 正誤に相当する演出(弾かれた時・GAME OVER時等)には、既存の`SeKind::Correct`/`Incorrect`と同様の効果音を鳴らす

## UI: 2視点構成

画面を左右に分割し、常に2つの視点を同時に表示する(縦分割にすると盤面が縦に狭くなりすぎるため)
- **視点1(軽トラ視点)**: 軽トラの荷台に乗った女の子キャラの静止画(通常時/踏ん張り時の2枚)と、信号の色等の背景要素。プレイヤーへの「Gが来る予兆」を伝える
- **視点2(盤面視点)**: ベーゴマ盤を真上から見た図。障害物・ゴール・ベーゴマの現在位置を表示する、実際の操作対象

他のゲームと同様、極端に小さい画面でもパニックしないことをテストで保証するが、実用的なプレイには一定の最小端末サイズを要する前提でよい。

## テスト観点

- 上下キー・左右キーの押下ごとに、該当する軸の傾きが一定量動くこと。連打の速さに応じて最大値への到達が速くなること(短い間隔で複数回押した場合と、間隔を空けて押した場合を比較する)
- キーを押していない間、時間経過で傾きが徐々に0へ戻ること
- 傾きが`-4`〜`+4`の範囲でクランプされること
- 信号ブレーキの制動Gが`a = v^2 / (2 * d)`で求まり、`d`が極端に小さい時も発散しないこと(下限クランプ)。気づくタイミングが遅い(dが小さい)ほどGが大きくなること
- 発進時の加速度、障害物回避時の横Gが、それぞれの式通りに速度・距離から求まること
- 段差の衝撃Gが速度に応じて変わること
- 盤の傾きに応じてベーゴマの速度・位置が変化すること(物理挙動の基本テスト)
- 平坦な場所ではGの大小に関わらず摩擦が変わらないこと
- 障害物にベーゴマが触れた瞬間のGの大きさに応じて、無影響/弾かれる/吹っ飛ぶの3パターンが正しく判定されること
- 吹っ飛んだ場合、即座にGAME OVER(失敗)になること
- 60秒以内にゴールに到達したら成功、到達しなければ時間切れで失敗になること
- 3.2.1.GO!!のカウントダウン後にベーゴマが投入されること
- メニューから選ぶと難易度選択を経由せず直接プレイが始まること
- 盤面画像の再エンコードが、ベーゴマの位置が変わった時だけ発生すること(盤面全体の作り直し回数が抑えられていること)
