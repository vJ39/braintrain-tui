## 概要

TTR(リズムゲーム)に2点の変更を行う。

1. 譜面トラックに小節の区切り線を表示する
2. 曲開始から最初の1小節(先頭4ビート)の間、各ビートに合わせてtick音を鳴らす

## 1. 小節ラインの表示

### 前提

`src/game/rhythm/beats.rs`の実測ビート時刻は4分音符ごとの時刻で、全曲4/4拍子を前提にしてよい(既存のセクション密度管理もビートインデックス単位で行っている)。よって「ビートインデックスが4の倍数(0, 4, 8, ...)」のビート時刻が小節の頭にあたる。

### 変更内容

- `rhythm.rs`に、`beat_times_ms`から4つおきのビート時刻を返すヘルパー(例: `fn measure_line_times_ms(beat_times_ms: &[u32]) -> impl Iterator<Item = u32> + '_`)を追加する
- `render()`内の描画ループで、ノーツの行位置(`row`)計算と同じ考え方(`progress = 1.0 - remaining_secs / SCROLL_TRAVEL_TIME`)を小節境界の時刻にも適用し、対応する行に小節ラインを描く
- 小節ラインは4レーン全体を貫く横線として表現する。ノーツの無いマスに敷いている`·`の代わりに、小節ラインの行だけ罫線文字(例: `─`)を敷く。ノーツがある場合はノーツの表示を優先する(小節ラインの行にノーツが乗っても、そのマスはノーツの●を表示する)
- 小節ラインの色は控えめにする(既存の`theme::MUTED`程度)。ノーツ・判定ラインより目立たせない

## 2. 最初の1小節のカウント音

### 前提

音源ファイルは用意せず、rodioでプログラム的に生成した短いビープ音(サイン波)を使う。ハンドクラップの質感は出ないが、tick音として機能させる。

### 変更内容

- `audio/mod.rs`に、ファイルを再生する既存の`play_se`とは別に、生成音を再生する関数(例: `pub fn play_tick()`)を追加する
- `RodioPlayer`に、`rodio::source::SineWave`を使って短いビープ音(周波数: 例880Hz、長さ: 例60ms、既存SEより控えめな音量)を生成し`Sink`に流すメソッドを追加する
- `RhythmGame`に、最初の1小節分(先頭4ビート、`song().beat_times_ms`の先頭4要素)のうち、まだ鳴らしていないビートを追跡するフィールド(例: `next_count_in_beat: usize`)を追加する
- `update()`内で、`now`(`started_at.elapsed()`)が次の未消化カウント音のビート時刻を過ぎたら`audio::play_tick()`を呼び、インデックスを進める。4ビート分(先頭1小節)鳴らし終えたら以後は何もしない
- BGMは曲頭から再生されるので、tick音は曲のビート時刻とタイミングが揃う(既存のノーツ判定と同じ`started_at`基準の時計を使うため)

## 対象ファイル

- `src/game/rhythm.rs`
- `src/audio/mod.rs`

## テスト観点

- `measure_line_times_ms`が4つおきのビート時刻を返すこと(ビート数が4の倍数でない曲でも境界外を含まないこと)
- 小節ラインの行がノーツの行位置計算と同じ`progress`の考え方で求まること
- render結果に、ノーツの無い小節境界の行で罫線文字が描かれること。ノーツがある場合はノーツの表示が優先されること
- 生成音の再生関数(`play_tick`等)が音声デバイスの無い環境でもパニックしないこと(既存の`play_se`/`play_bgm_track`と同様に`handle`が`None`なら何もしない)
- ゲーム開始直後、最初の4ビートの時刻に到達するたびに`next_count_in_beat`が進むこと。5番目以降のビートでは進まない(鳴らさない)こと
- 既存のTTR関連テスト(判定・譜面生成・コンボ等)が壊れていないこと
